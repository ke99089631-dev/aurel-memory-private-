# 2026-10-26 (月)

## 携帯チャット「どの部屋でも返答なし」障害 → 復旧

会長報告(09:12): 携帯チャットのどの部屋でも「(返答なし)」が出る。確認・復旧依頼。

### 切り分けた事実
- **認証**: トークンは今朝08:04に更新・有効(期限16:04)。原因ではない。
- **SDK/モデル**: `claude-opus-4-8` も claude.exe(`-p --output-format json`)も最小形・aurel完全引数・`--resume`経路すべて手動成功。claude層は健全。
- **aurel.mjs(PCコンソール/7878)**: 正常(http=200/401)。今朝08:59再起動されていた。
- **携帯サーバ側ログの実発生**: `(返答なし)` は home 08:02 / 壁→壁(trade) 08:52 に実記録(`via:phone`)。
- **ライブ疎通(Tailscale IP 100.73.107.61 経由)**: hub8787/carsales8789/acquisition8790/trade8792 は http=200。**aurel指令室8788 だけ exit7=接続拒否(netstatはLISTENINGなのに accept してない=ハング)**。

### 原因(確定)
2つの層:
1. **一過性**: 08:00〜08:52 にトークン期限切れ(?)で全部屋の claude.exe が空応答→「どの部屋でも返答なし」。08:04更新で claude 層は自己回復。
2. **居残り**: その障害中に**指令室(aurel)の携帯サーバ(pid8520, Python312版)が不正状態でハング**。OSはLISTENING表示のまま接続を拒否し続け、復旧後も「返答なし」が継続。

### 復旧(実施)
- `restart_room.ps1 -Room aurel -Port 8788` でハングした8520と、同時に居残っていた**ゾンビ二重起動の venv版840も両方停止**→venv版1本(pid4076)だけ再起動。8788リスナー=1(二重起動も解消)。
- 全5部屋 http=200 確認。指令室に実メッセージ投入→`status:done / reply:"OK"` = claude応答まで疎通確認。

### 学び / 予防メモ
- 携帯サーバは **2026-09-23 17:24 から venv版(start_chat_rooms.vbs)と Python312版の二重起動が共存**(trade は10-10)。SO_REUSEADDR で後発の py312 版がポートを握る。1ヶ月平常動作していたので二重起動自体は今回の主因ではないが、片方がハングすると復旧が分かりにくい潜在リスク。将来は launcher を1系統に統一したい。
- 症状「携帯で返答なし」の切り分け順: ①.credentials.json の期限 ②claude.exe を手動 `-p --output-format json` ③Tailscale IP 経由で各ポート `curl` (netstat の LISTENING は当てにならない=ハングでも残る) ④該当室を `restart_room.ps1` でクリーン再起動。
