## R-02 死んだレンジ票 v1(2026-11-10 会長GO・事前固定 → 同日判定済み)

- **会長の言葉**: 「抜けそうで抜けない死んだレンジも負けゾーンでは?」
- **定義 v1**: dead = 直前10本のダマシ率≥60% かつ 紙の直近連敗≥3(いずれも各時点の過去だけで計算・先読みなし)。スクリプト discretionary/live/deadrange_label.py。
- **節目/判定(書いた時点)**: dead側30本到達時、dead平均R<0 かつ 非deadとの差≤-0.2R なら執行機側の扱い(見送り/lot半分)を提案。
- **判定結果(2026-11-10 10:19・遡って付けたら既に50本)**: dead 50本 +0.10R / 非dead 273本 +0.19R / 差 -0.08R → **条件を満たさず・不採用**。deadの負けはトレンド地合い(6本 -0.73R)に偏り、チョップ内では dead +0.23 = 非dead +0.22 で差なし。
- **解釈**: 会長の「死んだレンジ」感覚をこの数式v1では捉えられていない(感覚が違うのでなく、物差しが違う可能性)。部品で見るとダマシ率30-60%帯 +0.41R(65本) vs 60%以上 +0.11R(242本) は残る(保管材料#2と一致)。連敗数は2-3で負・4+で正=ノイズ級。
- **次**: ラベルは付け続ける(日次集計に同梱)。会長のゾーン票(Z-xxxx)が30票貯まったら、票 vs deadラベルの一致率を測る=感覚の中身を探す。定義v2を書くときは新番号(R-02b)で。

## R-06 4本目の見張り線「遅れの溜まり」(2026-11-28 会長GO「goしてくれ」・事前固定)

- **背景**: 11/16-21 と 11/23-27 の2週で88本 +0.39R(週の標準偏差は約9.1Rなので数字自体は無意味)。だが平均は薄まっている(直近2週を除く355本 +0.128R / 直近88本 +0.004R / 全443本 +0.104R)。**R-05の3本はすべて「大きく負けたら鳴る」設計で、この「増えなくなる」動きはどれにも映らない**。会長の11-28 GO=「じわじわ薄くなるのを見張る線を事前固定で足す」。
- **物差し**: R-05と同じ **紙・再加速の正味R**(時間帯スプレッド中央値+手数料控除・break_time順・確定本のみ)。
- **式(下向きCUSUM=累積和管理図)**: `S_i = max(0, S_(i-1) + (k - R_i))`、`k = 0.052`。
  - 平たく言えば「1本あたり0.052R(今の実績ペースの半分)にも届かない**遅れ**を足し続ける。伸びた本があれば遅れは減る。マイナスにはならない」。
  - **警報線 h = 80.0**。S が 80 に達したら鳴る。
- **パラメータの決め方(数字を見て選んでいないことの記録)**:
  - `mu0 = +0.104`(全443本の正味平均・**私が選んでいない=台帳が決めた値**)。
  - `mu1 = 0.000`(検出したい劣化=「優位が消えた」)。`k = (mu0+mu1)/2` は CUSUM の教科書どおりで、恣意の余地なし。
  - `h` は **誤警報の予算を先に固定してから**決めた: 「何も壊れていないのに1年(2000本)のうちに鳴る確率 ≤ 10%」。校正は実台帳の残差のブロックブートストラップ(ブロック長20本=連敗のまとまりを保つ)・乱数種20261128・2500回。
  - 校正結果: h=60→誤警報13.5%(予算超え) / **h=80→3.6%(採用)** / h=100→0.8%。スクリプト `tmp/cusum_calibrate2.py`。
- **検出の速さ(会長が買っているものの正体・先に明示)**: 本当に平均が0になっていれば **中央1051本=約26週(半年)** で鳴る。これは設計の甘さではなく**この型の揺れの大きさ(sd 1.38R/本)が決める下限**。速くしたいなら誤警報を受け入れるしかない(h=60で11か月→誤警報13.5%)。
- **前向き開始**: **2026-11-28 以降の新規確定本から S を 0 から積む**。過去443本には当てない(当てれば後出しになる)。参考値として過去の積み上がりは併記するが判定には使わない。
- **触れた時にすること**: R-05と同じ。レシピ(入口/SL/TP)は変えない。**サイズ縮小 or 休止**を会長に提案し、会長GOで実行。
- **出力**: `danger_gauge.py` に4本目として実装済み(2026-11-28 11:30・日次 AUREL_ReaccelReports に同梱)。定数は `CUSUM_K / CUSUM_H / CUSUM_SINCE`。状態は持ち越さず毎回台帳から積み直す(=改ざんの余地なし)。旧版のバックアップ `danger_gauge.py.bak_20261128_r06`。
- **初回の値(2026-11-28 11:30)**: 前向き1本・遅れ 1.1 / 線 80。

### R-05② の線の格付け直し(2026-11-28・AURELの申告・会長の判断待ち)
- 同じ校正を R-05②(山からの落ち幅 -15R)に当てると、**何も壊れていなくても1年で触れる確率 99.9%**。
- しかも**この型は既に1回越えている**: 最大の落ち幅 **-17.51R**(山=75本目 2026-09-30 → 谷=115本目 2026-10-06・-15Rを下回った状態が10本続いた)。R-05を書いた11-17より前の出来事。
- つまり R-05② は「めったに触れない線」ではなく「**いつか必ず鳴る線**」。鳴っても優位が死んだ証拠にはならない。
- 落ち幅の線を診断器として機能させるには -50R 級が必要(= 資金管理の線としては意味がない水準)。
- **AURELの申告**: R-05② は **資金管理の線**(これ以上の痛みは引き受けない)であって**型の診断ではない**。2つの仕事が混ざっている。R-05②の文面を「診断」から「痛みの上限」に書き替えるかは**会長の判断**。線の値(-15R)は動かさない提案(想定DD-10.6Rの1.4倍=痛みの上限としては妥当)。
