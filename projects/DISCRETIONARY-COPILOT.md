## 設計（起案 v0）
### 段A 読むだけ台帳（金ゼロ・自律可）
- `discretionary_journal.py`: Vantage 端末へ path 名指しで読取アタッチ → `history_deals_get` / `positions_get` で約定を取り、エントリー/エグジット前後の M1/M5 バーを同時保存 → `data/discretionary/journal.sqlite`。
- 口座ガード: login==27972608 でなければ即停止。order_send 系 API は import すらしない。
- 形のタグ付け: 会長が (a) MT5 注文コメント欄に "A" などを書く / (b) チャットで「今のは形A」と言う / (c) 後でまとめて印を付ける。
- 出力: 朝の報告に裁量成績表（本数・勝率・平均R・DD・形別）。

### 段B 形の機械定義（会長の言葉→ルール）
- 会長が形を言葉で説明（時間足・銘柄・入る条件・損切/利確の置き方・見送る条件）→ AUREL が Python でルール化 → 過去バーで検出 → **会長の実トレードと突き合わせ、一致率で定義を校正**。
- 一致率が低い＝言葉にならない感覚が残っている部分。そこを分解して定義を詰める。

### 段C 期待値の測定（二車線）
- 車線1: 会長の実トレード台帳（n 小・本物の血）。
- 車線2: 機械定義の過去検出（n 大・紙）。edge_screen と同じ関門（前70/後30・実測コスト差引・FDR・時代持続）を **import** して通す。
- 判定は数字で出す。基準は測る前に固定（結果を見て動かさない）。

### 段D インジケータ化（MQL5）
- 段C を通った定義を `.mq5` インジケータに移植（矢印・アラート・push通知）。PC の Vantage 端末に置く。
- ★ MT5 スマホアプリはカスタムインジケータを動かせない → PC 端末で走らせ、MetaQuotes ID の push 通知で携帯へ飛ばす。
- 発注は一切しない（EA にはしない）。

## 会長回答（2026-09-20）
- トレードは **iPhone / Android から**（PCからではない）。→ PCのMT5は「読取用に同口座でログインしたまま常時起動」が前提。携帯で引いた線はPCへ同期しないので壁はチャット登録。
- 「検証は一緒に沢山やってきた。君のほうが詳しいかも」→ 機関の関門（edge_screen/soldier_screen）を import で流用する方針で回答。
- Aurelian との相性＝「頭は共有・手と財布は別」で良い。共有＝関門・コスト表・血（FOMC日程/レジーム）・台帳のハッシュ鎖作法・朝報告。非共有＝口座・発注器・コード経路。

## 壁登録の書式 v0（2026-09-20 提案・会長確認待ち）
- 事前: `壁 2365/2380/2395/2410`（水準列挙→隣接がボックス）／`次 上2410 下2365`／`狙い 上抜け|下抜け|両方`／`感触 強|普通|弱`＋自由メモ。返信で ID（W-0001）・登録時刻・登録時価格・次壁までの距離。
- 崩壊点: `崩壊 W-0001 2378 理由…`（SL位置＝仮説崩壊の定義。MT5のSL値は収集器が別途記録）。
- 途中: `触りたい 2401 理由…`（衝動の記録・行動なし）。
- 事後: `事後 T-0001 ダマシ|普通|きれい メモ…`。
- 対照群: `見送り W-0001 理由…`。取消: `取消 W-0001`。訂正: `訂正 W-0001 …`（旧行は残す・追記のみ）。
- 収集器がエントリーを検知→同銘柄・同方向の直近 open 登録に自動紐付け→「T-0001 ← W-0001」を返信。紐付け先が無ければ「事前登録なし」印。
