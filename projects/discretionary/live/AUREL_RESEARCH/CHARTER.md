## 確定した教訓（ここから逸脱しない＝入口フィルタを再発明するな）
1. 入口のフィルタ（ピンバー/壁種/足/天気/連敗縮小/建値SL/TP短縮/chase追加）は**全部、原型に負けた**。勝ち負けは入口で見分けられない（同条件から分岐）。
2. 優位は薄く（再加速 +0.18R gross・勝率50%）、**少数の大当たり（fat tail）に全部乗っている**。尻尾を削る工夫は優位を消す。
3. 実弾の優位は**スプレッド（執行コスト）に食われる**（紙+0.17 ≈ 執行−0.18 で相殺）。狭いスプレッドが最大の敵。
4. 効く可能性があるのは入口の賢さでなく「**構え**」＝サイズ/保有/同時本数/地合い（レジーム）/出口（path情報）。
→ **狙うのは**: 人間が頭で追えない高次元・**出口/path**・**レジーム**・**市場横断**・**我々の実験のメタ分析**。入口の単発フィルタは禁止。

## 規律（過適合を殺す）
- ルールを提案するなら、**検証の前に事前固定**（閾値・窓・定義を先に findings に書いてから回す）。
- **必ず 在サンプル / 外サンプル(OOS) で割る。** 在だけ良くても採用しない。
- 覆った知見・ゼロの知見も**消さない**（findings に残す。将来再現すれば昇格）。
- 1サイクル = **1つの focused な問い**。欲張らない。
- 毎回自問: 「これは機械的に当たり前では？ 大当たりを削ってないか？ 在だけで良く見えてないか？」

## 1サイクルの手順
1. この CHARTER・`backlog.md`・直近の `findings/` を読む。
2. backlog から1つ選ぶ、または新しいAIらしい問いを立てる（立てたら backlog に追記）。
3. 分析を書いて回す（python・読取りのみ・使うデータは下記）。**事前固定→在/外で検証。**
4. `findings/<YYYY-MM-DD>.md` に1エントリ追記（下の書式）。positive でも null でも必ず残す。
5. `backlog.md` を更新（済みに印・新しい枝を追加）。
6. 昇格候補（事前固定＋OOS通過＋大当たりを削ってない）だけ `PROMOTED.md` に移し、1行で会長向け要約を書く。
7. 何も出なくても「<日付> cycleN: <問い> → null（理由）」を findings に必ず残す。

### findings エントリ書式
```
## <YYYY-MM-DD HH:MM> cycleN — <問い1行>
- 事前固定: <定義・閾値・窓（検証前に決めたもの）>

- 判定: null / 弱い兆候(要継続) / 昇格候補
- 次の枝: <あれば backlog へ>
```

## 視点の種（指定でなく種。自分で広げてよい。金融市場全体を使ってよい）
- **出口/path**: 建玉中の値動きに情報があるか（非始動の早畳み・動的出口）。※入口でなく出口。[2026-11-04 初回で+0.5R到達の割れを発見済・findings参照]
- **レジームメーター**: 客観的・連続の指標で優位が条件づくか。「原型は何もしない、ただしメーターが緑の時だけ撃つ」。切替ルールは事前固定。
- **市場横断**: 同じ壁→壁構造を多数の銘柄（BTC/指数NQ/FX/商品）で回し、同じ構造がどこで払うか（AssetEmpire の cross_market.py 参照）。相関と合成DDも。
- **メタ**: 我々の過去の全実験をデータとして扱い「フィルタの尻尾削り量＝成績低下量」の法則を定式化。tail集中度（Gini/上位10%寄与）と**本当に必要なサンプル数**。
- **生存/ハザード分析**: TP対SLのハザードを建玉時間で。最適な時間切れ。
- **執行モデル**: スプレッド/注文種別で実弾netがどう動くか（業者選び・寄せ方の材料）。
- **市場全体のレジーム**: 金だけでなくドル/金利/VIX/他商品の状態が壁→壁の優位をどう条件づけるか。
